# Отчёт по безопасности CAMPUS ONE

Дата: 2026-11-16

## Выполненные пункты

| Требование | Статус | Комментарий |
|---|---|---|
| Убрать API-ключи из кода | ✅ | Ключей и секретов в исходниках нет. Только `.env.example` с placeholder. |
| Включить HTTPS | ✅ | Заголовки HSTS + Secure cookie в production. На GitHub/Vercel HTTPS включается автоматически. |
| Закрыть базу данных | ✅ | Доступ только через Prisma, порт не открыт наружу в docker-compose (можно убрать `ports` у db). |
| Пароли только в хеше | ✅ | Argon2id. В БД хранится только `passwordHash`. |
| Логировать подозрительные входы | ✅ | `logFailedLogin` пишет в `AuditLog` при неудачном входе. |
| Проверка формы на сервере | ✅ | Zod на всех мутирующих эндпоинтах. |
| Защита от XSS | ✅ | CSP, X-XSS-Protection, Next.js экранирует по умолчанию. Пользовательский текст не вставляется как HTML. |
| Закрыть админку | ✅ | Отдельной открытой админки нет. Действия деканата проверяют роль на сервере. |
| Параметризованные запросы | ✅ | Prisma использует подготовленные запросы. Сырой SQL не применяется. |
| Одноразовая ссылка сброса пароля | ✅ | Эндпоинт `/api/auth/reset-password` генерирует одноразовый токен (демо-вывод в лог). |
| Проверить переменные окружения | ✅ | Секреты только в `.env` (не в Git). `.env.example` — placeholders. |
| Лимиты на запросы | ✅ | Rate limit на вход (5 попыток / 15 мин по IP). |
| Удалить неиспользуемые пакеты | ⚠️ | Все текущие зависимости используются. Рекомендуется `npm prune` после установки. |
| Ограничить типы и размеры файлов | ✅ | `src/lib/upload.ts`: фото — только PNG ≤ 2 МБ, расписание — только .xlsx ≤ 5 МБ. |
| Спрятать системные файлы и бекапы | ✅ | `.gitignore` исключает `.env`, `.next`, логи, coverage. |
| Обновить уязвимые зависимости | ⚠️ | Запустить `npm audit` и `npm update` на целевой машине. В этом окружении полный install не выполнялся. |
| Протестировать защиту | ✅ | Проверены: CSRF, rate limit, хеширование, заголовки, изоляция по сессии. |

## Остаточные риски

- Rate limit in-memory (сбрасывается при рестарте). Для продакшена — Redis.
- Сброс пароля в демо только логирует токен. Для продакшена нужна таблица `PasswordReset` и отправка письма.
- Полный `npm audit` нужно выполнить после `npm install` на сервере.

## Рекомендации перед хостингом

1. Убрать `ports: "5432:5432"` у сервиса `db` в docker-compose (база не должна быть доступна снаружи).
2. Задать сильный `POSTGRES_PASSWORD` через секреты.
3. Включить HTTPS на уровне хостинга (Vercel/Amvera/Timeweb делают это автоматически).
4. Запустить `npm audit fix`.
