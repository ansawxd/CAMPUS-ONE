# Отчёт по безопасности CAMPUS ONE

Дата: 2026-11-19 (два прохода аудита кода)

## Найдено и исправлено

| # | Уязвимость | Где | Что сделано |
|---|---|---|---|
| 1 | **Утечка хешей паролей.** `GET /api/requests` отдавал `student.user` целиком, включая `passwordHash`. Заявки (и хеши) видели и преподаватели, и любые не-студенческие роли | `api/requests/route.ts` | Отдаются только нужные поля (`fullName`). Все заявки видят только деканат и админ |
| 2 | **Обход CSRF.** Запрос без заголовка `Origin` или с некорректным `Origin` пропускался | `lib/csrf.ts` | Мутирующий запрос без совпадающего `Origin` отклоняется (403) |
| 3 | **Перебор логинов.** Разные ответы «Пользователь не найден» / «Неверный пароль» | `api/auth/login` | Одно сообщение «Неверный логин или пароль» + проверка против фиктивного хеша, чтобы не выдавать логин по времени ответа |
| 4 | **Обход лимита попыток.** Лимит только по `X-Forwarded-For`, который подделывается; успешные входы тоже съедали лимит | `lib/security.ts` | Лимит по IP **и** по логину, считаются только неудачные попытки, сброс после успешного входа |
| 5 | **Журнал неудачных входов не работал.** Запись с фиктивным `userId` падала на внешнем ключе и молча терялась | `lib/security.ts`, схема | `AuditLog.userId` стал необязательным (миграция), лог реально пишется |
| 6 | **Токен сброса пароля в логах сервера** | `api/auth/reset-password` | Генерация и печать токена убраны; сброс — через деканат |
| 7 | **База открыта наружу** с паролем `postgres` (`ports: 5432:5432`) | `docker-compose.yml` | Порт привязан к `127.0.0.1` (и перенесён на 5433) |
| 8 | **Петля редиректов** при протухшей cookie (`/` → `/login` → `/`) | `middleware.ts` | Редирект с `/login` убран, сессию проверяет layout кабинета |
| 9 | **Нет выхода из аккаунта** (сессию нельзя было отозвать) | — | `POST /api/auth/logout` + кнопка «Выйти» |
| 10 | **Нет лимитов длины** у заметок и заявок (можно залить мегабайты) | `api/notes`, `api/requests` | Ограничения Zod: 2000 / 1000 символов |
| 11 | **Лишние данные в новостях** — список всех лайков с `userId` | `api/news` | Отдаётся только количество лайков |
| 12 | **`passwordHash` в объекте текущего пользователя** во всех страницах | `lib/auth.ts` | `getCurrentUser()` вырезает хеш |
| 13 | **CSP ломал React в dev-режиме** → форма входа могла уйти обычным GET с паролем в адресной строке | `next.config.ts`, форма входа | `unsafe-eval` только в dev, форма `method="post"`, добавлены `frame-ancestors`, `base-uri`, `form-action` |
| 14 | Смена статуса заявки всегда падала (`params` в Next 15 — Promise), несуществующий id → 500 | `api/requests/[id]` | `await params`, проверка UUID, 404 |

Зависимости: Next.js 15.5.29 и sharp 0.35.5 — версии с исправлениями опубликованных уязвимостей (React2Shell CVE-2025-55182 / CVE-2025-66478, DoS в Server Components, октябрьский патч 15.5.28).

## Проверено, в порядке

- Пароли — Argon2id, в БД только хеш; cookie сессии `httpOnly`, `sameSite=lax`, `secure` в production
- В БД хранится только SHA-256 от токена сессии
- Prisma — параметризованные запросы, сырого SQL нет
- React экранирует пользовательский текст, `dangerouslySetInnerHTML` не используется
- Заметки и заявки студента изолированы по владельцу на сервере (в т.ч. удаление заметки по чужому id)
- `.env` не в git

## Остаточные риски (для демо допустимо)

- Лимит попыток в памяти процесса — сбрасывается при перезапуске. В проде — Redis.
- Лимит по логину позволяет злоумышленнику на 15 минут заблокировать вход чужому аккаунту (компромисс ради защиты от перебора).
- CSP содержит `'unsafe-inline'` для скриптов (нужно Next.js без nonce).
- Сброс пароля по почте не реализован.
- `npm audit` в среде аудита не запускался (нет доступа к реестру npm) — выполните `npm audit` у себя.

## Перед публичным хостингом

1. Сильный `POSTGRES_PASSWORD` через секреты хостинга.
2. HTTPS на уровне хостинга.
3. `npm audit fix`.
